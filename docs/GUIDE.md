## 2. 用語の解説

> それぞれの道具がどうつながって動いているか（全体図）は [STACK.md](STACK.md) にまとめています。

### HTML / CSS / JavaScript（土台の3つ）
- **HTML**：ページの「骨組み」。見出し・文章・リンクなどを並べる。
- **CSS**：ページの「見た目」。色・大きさ・配置を決める。
- **JavaScript（JS）**：ページの「動き」。クリックしたら何かが起きる、などの処理。

ブラウザが最終的に理解できるのはこの3つだけです。以下の道具はすべて、この3つを **楽に・安全に・効率よく** 作るためのものです。

### TypeScript（タイプスクリプト）
JavaScript に「型（データの種類のルール）」を足した言語です。
たとえば「名前は文字列、年齢は数字」と決めておくと、うっかり間違えたときに **実行する前にエディタが赤線で教えてくれます**。書いたものは最終的に JavaScript に変換されてブラウザで動きます。
→ このプロジェクトでは `src/data/profile.ts` の `type Work = {...}` がその例です。

### React（リアクト）
画面を「部品（コンポーネント）」に分けて作るための **ライブラリ** です。
ヘッダー、カード、ボタンなどを部品として一度作れば、何度でも使い回せます。HTML に似た書き方（JSX）で JavaScript の中に画面を書きます。
→ `src/components/Header.tsx` や `Section.tsx` が部品です。

### Next.js（ネクスト・ジェイエス）
React を使って **Webサイト全体** を作るための **フレームワーク** です。
React は「部品を作る道具」、Next.js は「部品を組み立ててサイトにする仕組み一式」と考えるとわかりやすいです。
- ファイルを置いた場所がそのまま URL になる（`src/app/page.tsx` → `/`）
- 画像やフォントの最適化、表示を速くする工夫が最初から入っている

### ライブラリとフレームワークの違い
- **ライブラリ**：必要なときに呼び出して使う「道具箱」（例：React）
- **フレームワーク**：作り方の「型」や「ルール」ごと提供される「枠組み」（例：Next.js、Angular）
Angular も Next.js と同じくフレームワークですが、React ではなく独自の仕組みを使います。同時に使うことはまずないので、このサイトでは Next.js を使います。

### Tailwind CSS（テイルウィンド）
CSS を **クラス名を並べるだけで書ける** ようにする道具です。
`className="text-xl font-bold"` と書けば「大きめの文字・太字」になります。別の CSS ファイルを行き来しなくてよいので、慣れると速く書けます。

### Node.js と npm
- **Node.js**：JavaScript をブラウザの外（自分のPC）で動かすためのソフト。Next.js を動かすのに必要です。
- **npm**：Node.js に付いてくる「道具の取り寄せ係」。`package.json` に書かれたライブラリをまとめてダウンロードします（`npm install`）。

### Git と GitHub
- **Git**：ファイルの変更履歴を記録するソフト。「いつ・何を・なぜ変えたか」を残せて、失敗しても前の状態に戻せます。
- **GitHub**：Git の履歴をインターネット上に保存するサービス。バックアップになり、就活では「どんなコードを書いてきたか」を見せる場所にもなります。

### Cloudflare（クラウドフレア）
作ったサイトを **インターネットに公開する（ホスティング）** サービスです。
このプロジェクトでは **Cloudflare Workers** を使います。友人のサイト（`〜.workers.dev`）と同じ方式です。無料枠で十分使えます。
Next.js を Cloudflare で動かすために **OpenNext（@opennextjs/cloudflare）** という変換ツールを入れています。

## 5. よく使うコマンド

ターミナル（Mac は「ターミナル」、Windows は「PowerShell」）で、`portfolio` フォルダに移動してから実行します。

| コマンド | 意味 |
|---|---|
| `npm install` | 必要なライブラリを取り寄せる（最初に1回） |
| `npm run dev` | 開発用サーバーを起動。ブラウザで http://localhost:3000 を開くと表示される。ファイルを保存すると自動で反映 |
| `npm run build` | 公開用にまとめて変換できるか確認する |
| `npm run preview` | Cloudflare と同じ環境で、手元で動作確認する |
| `npm run deploy` | Cloudflare に公開する（Cloudflare へのログインが必要） |

> 変更を GitHub と公開サイトに反映する手順は、場面別に [UPDATE.md](UPDATE.md) にまとめています。普段は GitHub に push（または PR をマージ）するだけで自動で公開されるので、`npm run deploy` は非常用です。

## 7. GitHub に保存する（ステップ③）

GitHub は「コードの保管庫」です。保管庫ひとつひとつを **リポジトリ（repository、略してリポジトリ／レポ）** と呼びます。

### あなたにやってほしいこと
1. **GitHub アカウントを作る**：https://github.com/signup （ユーザー名は就活でも見られるので、本名に近いものや読みやすいものがおすすめ）
2. **空のリポジトリを作る**：ログイン後、右上の「＋」→「New repository」
   - Repository name：`portfolio`
   - 公開範囲：**Public**（就活で見せられる。メールアドレスなどの秘密はコードに入れていないので公開して大丈夫）
   - 「Add a README」などのチェックは **すべて外したまま**（中身はこちらから入れるため）
   - 「Create repository」を押す
3. **Claude と GitHub をつなぐ**：https://claude.ai/connect-github を開いて連携し、続けて「Claude」アプリをインストールする画面で、さきほどの `portfolio` リポジトリを選ぶ

ここまで終わったらスレッドで教えてください。こちらで今あるコードと変更履歴をそのリポジトリにアップロード（**push／プッシュ**）します。

### 用語メモ
- **コミット（commit）**：変更を「セーブポイント」として記録すること。いつ・何を変えたかのメッセージを付ける
- **プッシュ（push）**：手元のコミットを GitHub に送ること

## 8. Cloudflare で公開する（ステップ④）

GitHub にコードが入ったら、Cloudflare に「このリポジトリが更新されたら自動でサイトを作り直して公開して」と設定します（**Workers Builds** という機能）。一度つなげば、以後はコードを GitHub に push するだけで公開サイトが更新されます。

1. **Cloudflare アカウントを作る**：https://dash.cloudflare.com/sign-up
2. ダッシュボード左メニュー「Workers & Pages」→「Create」→「Import a repository」（GitHub と連携を求められたら許可）
3. `portfolio` リポジトリを選び、設定を次のようにする
   - Project name：`portfolio`（`wrangler.jsonc` の `name` と同じにする）
   - Build command：`npx opennextjs-cloudflare build`
   - Deploy command：`npx opennextjs-cloudflare deploy`
4. 「Deploy」を押すと数分で `https://portfolio.＜あなたのサブドメイン＞.workers.dev` という URL ができます

詳しい手順は、GitHub への保存が終わった時点で画面に合わせて案内します。

## 9. 中身とデザインを自分仕様にする（2026-11）

### 中身（データ）の変更
- 名前・自己紹介・スキル・作品・経歴は **`src/data/profile.ts`** にまとめています。文章を直したいときはここだけ触れば OK
- スキルは `{ name: "Java", note: "研究" }` のように **どこで使ったか** をメモできる形にしました（画面では「Java（研究）」と表示）
- 経歴（Career）セクションを追加。`education`（学歴）・`experience`（アルバイト）・`certifications`（資格）の 3 つの配列に 1 行ずつ書き足せます
- 作品が増えたら `works` に `{ title, description, tech, url }` を追加するだけでカードが増えます

### デザインのテーマ：「森の中のエンジニア」
- 「自然の中で植物に囲まれている感じ。でもテクノロジー感は残す」というイメージで作っています
- 最初の画面は、上からたれ下がるツル・左右から伸びる枝・足元の茂みで **四方を植物で囲み**、木漏れ日の光の筋と、ふわふわ漂う光の粒（ダークモードでは蛍）を重ねています
- テクノロジー感は、ターミナル風の自己紹介、等幅フォント（コードの文字）、`// 01.` のようなコメント風の見出し、方眼ノート風のドット背景、**回路のように光る葉脈** で出しています
- 色は `src/app/globals.css` の `:root` で決めています。葉っぱは `--leaf-1`（奥・薄い）〜 `--leaf-4`（手前・濃い）の 4 段階で、色の濃さの違いで奥行きを出しています
- ダークモードは「夜の森」。手前の葉がシルエットになり、葉脈が緑に光ります

### 動き（アニメーション）の仕組み
新しいライブラリは入れず、ブラウザ標準の機能だけで作っています（サイトが軽いまま、仕組みも学びやすい）。

| 動き | ファイル | 使っている仕組み |
|---|---|---|
| いろいろな植物の形（ツル・ポトス・ユーカリ・シダ・ヤシ・モンステラ・草・小さな花） | `src/components/nature/Plants.tsx` | **SVG**（コードで描く画像）。葉の形を差し替えるだけで別の植物になるように作っている。葉の位置は「ベジェ曲線」の計算で並べる |
| 植物が伸びて出てきて、風でゆれる | `src/app/globals.css` | CSS の `@keyframes`（`.grow` と `.sway`） |
| どこにどの植物を生やすか | `src/components/nature/Foliage.tsx` | `palm(...)`・`monstera(...)` のような短い関数で植物のデータを作り、配列に並べる |
| 木漏れ日・光の粒（蛍） | `src/components/nature/Atmosphere.tsx` | 半透明のグラデーションや丸を CSS で動かす |
| スクロールすると葉が奥行きをもって動く | `src/components/ScrollDepth.tsx` | スクロール量を CSS 変数 `--sy` に入れ、奥の葉ほどゆっくり動かす（**パララックス効果**） |
| スクロールするとふわっと出てくる | `src/components/Reveal.tsx` | **IntersectionObserver**（要素が画面に入ったらブラウザが知らせてくれる）＋ CSS の `transition` |
| ターミナルに文字が打ち込まれる | `src/components/Terminal.tsx` | React の **useState / useEffect** で 1 文字ずつ表示を増やす。全部の行を最初から透明で置いて枠の高さを固定し、結果の行はフェードインさせる（ガタつき防止） |
| カードにマウスを乗せると浮く | `src/app/page.tsx` | Tailwind の `hover:` と `transition` |

植物を増やしたい・減らしたいときは、`Foliage.tsx` の配列に `fern(...)` や `flower(...)` を 1 行足したり消したりするだけで OK です。

### 用語メモ
- **"use client"**：ファイルの先頭に書くと「この部品はブラウザで動く」という意味。スクロールの見張りやタイマーなど、ブラウザでしかできないことに必要
- **useState**：画面に出す値を覚えておく箱。値が変わると画面が自動で描き直される
- **useEffect**：画面が表示されたあとに実行したい処理（タイマー開始など）を書く場所
- **SVG**：線や図形を「座標」で描く画像形式。拡大してもぼやけず、CSS で色や動きを付けられる
- **パララックス**：手前のものは速く、奥のものはゆっくり動かすことで、立体的な奥行きを感じさせる演出
- **@keyframes**：CSS で「最初はこう → 最後はこう」とアニメーションの流れを決める書き方
- **レイアウトシフト**：表示中に要素の大きさが変わって、まわりがガタッと動くこと。アニメーションがカクついて見える大きな原因なので、先に場所を確保しておくのがコツ
- **backdrop-blur**：後ろをすりガラスのようにぼかす効果。きれいだが、後ろで何かが動いていると毎回ぼかし直すので重くなる
- **prefers-reduced-motion**：OS で「動きを減らす」を選んでいる人向けに、アニメーションを止める設定。見る人への配慮として入れています

## 10. スクロール演出・3D・イラスト・自動ダークモード（2026-11）

「動き」と「絵」で、文章を読む前に雰囲気と情報が伝わるようにしました。
どこに何の絵を置いたか・その理由は **[DESIGN.md](DESIGN.md)** にまとめています。

### 追加したもの

| 機能 | ファイル | 使っている仕組み |
|---|---|---|
| 時間帯でライト/ダークが自動で変わる | `src/lib/theme.ts`、`src/app/layout.tsx` | ページが表示される **前** に小さなスクリプトで時刻を見て、`<html data-theme="dark">` のように印を付ける。CSS はこの印を見て色を切り替える |
| ライト/ダークを手動で選ぶボタン | `src/components/ThemeToggle.tsx` | 押すたびに「自動 → ライト → ダーク」。選んだものは **localStorage**（ブラウザの小さな保存場所）に保存 |
| 読んだ量に合わせて伸びるツル | `src/components/ScrollVine.tsx`、`ScrollDepth.tsx` | 画面の幅に合わせて、くねくねした茎（ベジェ曲線）・葉っぱ・巻きひげの SVG を作る。スクロール量（0〜1）を `--sp` に入れ、茎は `stroke-dashoffset` で読んだ分だけ描き、葉と巻きひげは茎の先が届いたら開く |
| ヒーローの文字が沈みながら消える | `globals.css` の `.hero-fade` | `--sy`（スクロール量）で透明度と位置を計算 |
| 経歴の縦線が茎のように伸びる | `src/components/ScrollLinked.tsx` | 要素を何割読み進めたかを `--p` に入れ、`scaleY(--p)` で線を伸ばす。スクロールを戻すと縮む。経歴は「上が過去 → 下が現在」の順に並べ、茎の伸びる向きと時間の流れをそろえている |
| 線画イラスト（アイコン 10 種類＋作品のイメージ図） | `src/components/illustrations/Icons.tsx` | SVG の path。画面に入るとペンで描くように線が伸びる（`stroke-dashoffset`） |
| 3D の浮かぶ森の小島 | `src/components/three/` | **three.js**。ドラッグで回る・マウスで傾く・スクロールで少し回る・昼は小さな花が芽を出して咲く・夜は蛍と画面が光る |

### 時刻を変えたいとき
`src/lib/theme.ts` の次の 2 行を変えるだけです。

```ts
export const DAY_START = 6; // 朝 6:00 からライト
export const NIGHT_START = 18; // 夕方 18:00 からダーク
```

### イラストを増やしたいとき
`Icons.tsx` の `ICONS` に `名前: ["線のデータ", ...]` を足し、`<Icon name="名前" />` で使います。
線のデータは、48×48 のマス目の上で「M（ペンを置く）→ l / h / v（線を引く）→ c（曲線）」と書いていく SVG の書き方です。
Figma などで描いた絵を「SVG としてコピー」して、`d="..."` の部分だけ持ってくることもできます。

### 3D の小島を変えたいとき
`islandScene.ts` の中で `add(形, 材質, x, y, z)` を 1 行足すと物が増えます。
例：`add(new DodecahedronGeometry(0.3, 0), m.rock, 1, 0.3, -1)` で岩が 1 つ増えます（x = 左右、y = 上下、z = 手前/奥）。
色は同じファイルの `PALETTE`（light が昼、dark が夜）で変えられます。

### 3D の花の咲き方
`islandScene.ts` の「昼だけ咲く小さな花」の部分です。花は「茎＋花びら 5 枚＋中心」でできていて、
花びらは 1 枚ずつ「ちょうつがい」のグループに入っています。ちょうつがいの角度を上向き（`CLOSED`、つぼみ）から横向き（`OPEN`、満開）へ変えると、花が開いて見えます。
花ごとに 15〜25 秒の周期で「芽が出る → 開く → 咲いている → 閉じて地面に戻る」をくり返し、咲き始めも 1 本ずつずらしています。
花の色は `FLOWER_COLORS`、本数は `count`、咲く速さは `SPROUT`・`OPEN_TIME` で変えられます。

### 用語メモ
- **WebGL**：ブラウザに入っている 3D 描画の機能。パソコンやスマホの GPU（絵を描く専用の部品）を使うので速い
- **three.js**：WebGL を簡単に使うためのライブラリ。「シーン（舞台）・カメラ・ライト・レンダラー（描画係）」をそろえ、舞台に「メッシュ（形＋材質）」を置いていく
- **動的 import**：`await import("./islandScene")` のように、必要になったときに初めてファイルを読み込む書き方。最初の表示を軽くできる
- **localStorage**：ブラウザに小さなデータを保存しておける場所。サイトごとに別々で、閉じても消えない
- **data 属性**：`data-theme="dark"` のように、HTML の要素に自由な印を付けられる仕組み。CSS から `[data-theme="dark"]` で選べる
- **ハイドレーション**：サーバーで作った HTML に、ブラウザ側で React が「動き」を後から付け足すこと。サーバーとブラウザで中身が違うと警告が出るので、時刻で変わる部分は工夫が必要（`suppressHydrationWarning`）
- **stroke-dashoffset**：線を「点線」として扱い、その点線をずらす CSS の設定。ずらす量を 1 → 0 に動かすと、線がペンで描かれていくように見える

## 11. もっと自然に・神秘的なジャングルへ（2026-11）

### ばらばらなのに、毎回同じ形：シード付き乱数
自然な見た目にするコツは「同じものを等間隔に並べない」ことです。そこで、ツルの波・葉っぱ・花の位置などを乱数で決めています。
ただし `Math.random()` だと表示のたびに形が変わり、サーバーで作った HTML とブラウザの画面がずれてしまいます。
そこで **`src/lib/random.ts` の `seeded(数字)`** を使っています。同じ数字（シード）からは、いつも同じ「ばらばらな数」が出てきます。
形を変えたいときは、シードの数字を変えるだけで別のばらつき方になります。

### ジャングルの奥行きの重ね方（奥 → 手前）
1. **遠くの木の幹**（`JungleTrunks`）：たくさんの細い幹を淡い色でぼかす → 霧の向こうにある感じ
2. **奥の光と霧**（`JungleMist`）：中央を明るく光らせ、ぼかした楕円をゆっくり横にただよわせる
3. **たれ下がるツル**（`Lianas`）：上から長さの違うツルを何本も。葉付き・実のような粒付き・葉なしを混ぜ、ゆっくりゆらす
4. 今までの植物（`HeroFoliage`）と光の粒
5. **手前の大きな葉のシルエット**（`JungleSilhouettes`）：バナナの葉やヤシの葉を、四隅に暗い影として置く。バナナの葉は 1 本のつながった輪郭で描き、ふちから主脈のほうへ斜めに入る細い切れ込みを数本入れて、風で裂けた本物らしい葉にしている（部品に分けて描くと、つなぎ目に細い線が見えて不自然になったため）。画面の下のはしでまっすぐ切れて見えないよう、下に向かって薄く消している（`.silhouette-fade`）
6. **四隅を暗くする**（`.jungle-vignette`）：森の奥をのぞきこんでいるような感じ

同じ考え方で、ページ全体の背景にも、左右のはしにだけうっすらと幹を置いています（`JungleBackdrop`）。
色は `globals.css` の `--trunk-far`・`--silhouette`・`--mist` などで、昼と夜で切り替わります。
参考にした絵は雰囲気（霧・光・手前の暗い葉）を観察しただけで、絵そのものは使わず、すべてコードで描いています。

### メモ：3D の小島の土台に「すき間」が見えた原因

小島の岩や木は、形をわざと少しでこぼこにしています（`islandScene.ts` の `roughen`）。
このとき「同じ場所にある頂点は同じだけ動かす」ようにしていますが、場所を文字（"0.000" など）にして比べていたため、
円の継ぎ目で計算の誤差から「-0.000」になった頂点が別の場所あつかいされ、別々に動いて面の間にすき間ができていました。
数字を丸めて -0 を 0 にそろえることで直しました。あわせて、土台の上の面を草地の中に少しもぐらせ、草地と土台の間のすき間も見えないようにしています。
